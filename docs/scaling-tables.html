Wallet-count scaling — full results

Each sender owns its own pool of 150 holdings and its own receiver, so wallets never touch each other's holdings. Input selection is a uniform random pick from the sender's own pool. The only variable is how many independent wallets the load is spread across.

The same code does 3x the throughput at 8 wallets (14.6 → 44.0/s), so ~15/s was never a registry ceiling. But scaling is sublinear and latency rises throughout — a second ceiling sits above wallet contention, and on this hardware it is almost certainly the participant rather than the registry.
