canton-stress · interface prototype

One command. A verdict, a cause, and a fix.

No workload file to author, no flags for the common case, and no percentiles to interpret. The tool reads the DAR, builds its own test data, runs, and answers the question the user actually asked. The numbers are the evidence; the verdict is the product.

What it replaces

Today the same run needs a hand-written JSON workload with setup steps and placeholder syntax, plus seven flags:

run x.dar --workload-file w.json --model closed --concurrency 8 --ops 240 --sandbox --java-home …
Three design rules

Never author a file. The DAR says what the templates and interfaces are; the tool can generate the workload and let it be edited later if needed.

Never make them read a percentile to get an answer. Report the verdict; keep the distribution for those who want it.

Always name the fix. A diagnosis without a remedy just moves the problem.

Why the FIX line is possible at all

Because contention has a model: contention ≈ (transfers ÷ holdings) ÷ 2. That is what turns "12.5% contention" into "hold 2,400 instead of 480." No general-purpose load tool can say this, because none of them know what a holding is.
